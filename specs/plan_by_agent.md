# ゲーム性向上ブレインストーミング

## 前提の整理

### コアの快感
- **身長が伸びる瞬間**が最も気持ちいい
- 「数値が上がる」だけでなく、**視覚的に伸びている**のが良い

### 守るべきもの
- シミュレータとしての自然さ（操作の手間を増やさない）
- 「背が高い人の人生を追体験する」というコンセプト

### 現状の課題
- 成長は楽しいが、成長の**意味**が薄い
- ドアを屈む＝ゲーム性だが、繰り返しは作業になる
- 「できること」が身長で変わらない

### 却下済みアプローチ
- **台詞追加**: 既存NPC反応（tall/huge/very_huge × ステージ別）の延長。量を増やしても新体験にならない
- **モノローグ**: 実装済みだが、毎学期発生すると鬱陶しくなった。テキスト反復は効果が薄れる
- **カメラ演出拡張**: 身長でカメラ引きは実装済み。2D横スクでこれ以上は不自然
- **空間フィットシステム**: 屈みシステムとして既に実装済み。このゲームのコアシステム

**→ 求めているのは「新しいゲームシステム」であり「既存コンテンツの増量」ではない**

---

## 思考法：システムとしてのゲーム性を考える

### 「台詞」と「システム」の違い

台詞 = 身長が変わるとテキストが変わる（出力が変わるだけ）
システム = 身長が変わると**ゲームの構造・ルール・インタラクション**が変わる

例：
- 台詞「天井が低いね」→ 読んで終わり
- システム「天井にぶつかるとリアクションが発生する」→ プレイヤーが空間を意識し始める

### 問いの立て方

> 「身長が変わったとき、プレイヤーの**行動・判断・注意**が変わるのはどんな場面か？」

テキストを読むだけでは行動は変わらない。
世界の物理的な制約や構造が変わると、プレイヤーは自然に行動を変える。

---

## ゲームシステム案

---

### S1. インタラクション高度システム

**コンセプト：身長によって「触れるもの」が変わる**

世界のオブジェクトに「高さ」属性を持たせる。
プレイヤーの身長（＝手の届く高さ）によって、インタラクト可能なものが変わる。

#### 具体例
- 棚の上のアイテム → 160cmで届く / 150cmでは届かない
- 高い窓の鍵 → 175cmで開けられる
- 低い遊具のトンネル → 130cmまでなら通れるが、大きくなると通れない
- 自動販売機のボタン → 子供のうちは背伸びが必要

#### ゲーム性
- **同じステージを再訪したとき、できることが違う**
- 成長＝新しいインタラクションの解放 + 旧インタラクションの喪失
- 「大きくなったからできる」と「大きくなったからできなくなった」の二面性

#### 実装コスト

| 項目 | 内容 |
|---|---|
| 新規要素 | オブジェクトに `interact_height_min` / `interact_height_max` プロパティ |
| 触るファイル | `StageBuilder.gd`（オブジェクト定義に高さ属性追加）、`MainScene.gd`（インタラクト判定に身長チェック追加） |
| 工数 | **中**（オブジェクト定義の拡張 + インタラクト判定ロジック） |
| 注意 | 既存のステージオブジェクトへの後付けが必要。段階的に追加可能 |

### S3. 服のサイズシステム

**コンセプト：成長すると服が合わなくなる → 買い替えが必要になる**

服に「対応身長レンジ」を持たせる。身長がレンジを超えると見た目が変わる
（袖が短い、裾が足りない等の描画変化）。新しいサイズを入手すると直る。

#### 具体例
- 制服が小さくなる → 袖が短く描画される / 裾が上がる
- 体操服がキツくなる → 微妙に体にフィットしすぎる描画
- サイズが合っていない状態がビジュアルで分かる
- 学期の節目で「新しい制服」を受け取るイベント（またはショップ）

#### ゲーム性
- **成長が視覚的に服に反映される** → 「あ、もう合ってない」という発見
- 服の買い替え/受け取りが**成長の節目を実感させるイベント**になる
- 身長という数値変化がファッションという目に見える結果に変換される

#### 実装コスト

| 項目 | 内容 |
|---|---|
| 新規要素 | 服データに `size_range` プロパティ、サイズ外の描画変形ロジック |
| 触るファイル | `CharacterClothingDrawer.gd`（サイズ不一致時の描画変形）、`Global.gd`（服のサイズ管理）、`MainScene.gd`（買い替えイベント） |
| 既存活用 | 服の描画システム（855行）は柔軟。パラメータ追加で変形表現可能 |
| 工数 | **中〜大**（描画変形のパラメータ調整とバランスが主な工数） |

---

### S4. 視界レイヤーシステム

**コンセプト：身長によって「見える情報」が物理的に変わる**

オブジェクトに「上面」の情報を持たせる。プレイヤーの目線が
オブジェクトの高さを超えると、上面が見えるようになる。

#### 具体例
- 棚の上 → ホコリ、忘れ物、隠されたアイテムが見える
- 塀の向こう → 超えた身長で先が見える
- 人混みの上 → 標識や看板が見える（NPCには見えない）
- ロッカーの上 → 誰かが隠したものが見える

#### ゲーム性
- **「高いからこそ見えるもの」という発見のご褒美**
- 同じステージでも身長ごとに見える情報が違う
- 環境観察が能動的な探索行為になる

#### 実装コスト

| 項目 | 内容 |
|---|---|
| 新規要素 | オブジェクトに `top_surface` 描画データ、表示判定ロジック |
| 触るファイル | `StageBuilder.gd`（オブジェクト上面定義）、描画レイヤー制御 |
| 工数 | **中〜大**（2D横スクで「上面が見える」を自然に表現する描画が難しい） |
| リスク | 2Dの視点制約と相性が悪い可能性。見下ろし表現の限界 |

---

### S5. 成長痛 / 体調システム

**コンセプト：急成長に伴う身体的コストをシステムとして表現**

急激に伸びた学期には「成長痛」が発生。移動速度低下や
特定のポーズが取れない等の一時的デバフが発生する。

#### 具体例
- 大きく伸びた直後 → 少しの間、移動速度が落ちる / 足を引きずるモーション
- 成長痛フラグ → 保健室に行くと回復（はるかとのイベントにもなる）
- 急成長期 → 「体がついていかない」感覚を操作感で表現

#### ゲーム性
- **成長にコストがある → 伸びることが一方的な良いことではなくなる**
- 伸びすぎると一時的にデメリット → シミュレータの「リアルさ」が増す
- 保健室＝回復拠点という新しいゲーム的意味が生まれる

#### 実装コスト

| 項目 | 内容 |
|---|---|
| 新規要素 | `Global.gd` に `growth_pain` フラグ + 持続期間、`SkeletalPlayer.gd` に速度補正 |
| 触るファイル | `Global.gd`（状態管理）、`SkeletalPlayer.gd`（移動補正）、`CharacterPoseCalculator.gd`（痛みポーズ）、`MainScene.gd`（保健室回復イベント） |
| 工数 | **小〜中**（コアは速度とポーズの補正だけ。保健室イベント込みで中） |
| 注意 | 「操作の不便さ」にならないよう、デバフの程度と頻度を慎重に調整 |

---

### S6. 環境干渉・リアクションシステム

**コンセプト：身長が物理的に世界に「当たる」**

プレイヤーの頭部位置とオブジェクトの干渉を判定。
ぶつかった時に自動リアクション（頭を押さえる、避ける等）が発生する。

#### 具体例
- ドア枠に頭が当たる → 「ゴン」+ 頭を押さえるモーション（1回だけ、次回から自動で屈む）
- 木の枝 → 頭に当たる / 自動で避ける
- 看板 → 顔の高さに来る看板にぶつかりそうになる
- **初回だけリアクション、2回目から学習（自動回避）**

#### ゲーム性
- **「初めてぶつかる」瞬間が発見イベントになる**
- ぶつかった後は自動回避 → 操作負荷は増えない
- 「この身長になるとここに当たるんだ」という身体的な気づき
- 身長が変わるたびに新しい干渉ポイントが生まれる

#### 実装コスト

| 項目 | 内容 |
|---|---|
| 新規要素 | オブジェクトに `collision_height` 属性、衝突→学習のステートマシン |
| 触るファイル | `StageBuilder.gd`（干渉高さ定義）、`SkeletalPlayer.gd`（衝突判定+自動回避）、`CharacterPoseCalculator.gd`（回避ポーズ） |
| 既存活用 | ドアの屈み判定がすでにある → これを汎用化する方向 |
| 工数 | **中**（ドアの屈み判定を一般化。オブジェクトごとの干渉定義が主な作業） |

---

### S7. 目標身長 / 身長予測システム

**コンセプト：「最終的にどこまで伸びるか」をプレイヤーの関心事にする**

成長カーブから予測身長を表示。予測がどんどん上方修正されていく
ことで、「どこまで伸びるんだ…」というワクワク（または不安）を生む。

#### 具体例
- 身体測定のたびに予測最終身長が表示される
- 成長グラフに予測ラインが延びる（破線）
- 実績的マイルストーン：「予測身長が190cmを超えました」
- NPCの反応にも使える（「将来180は超えるね」→ 実際はもっと伸びる）

#### ゲーム性
- **未来への期待感がモチベーションになる**
- 成長グラフがただの記録ではなく「予測ゲーム」になる
- プレイヤーの関心が「次の学期」に向く → 学期を進めたくなる

#### 実装コスト

| 項目 | 内容 |
|---|---|
| 新規要素 | 成長カーブに基づく予測計算関数、予測表示UI |
| 触るファイル | `Global.gd`（予測計算）、`GrowthGraph.gd`（予測ライン描画）、`MainScene.gd`（測定結果表示に予測追加） |
| 工数 | **小〜中**（計算ロジック自体は簡単。UI表示が主な工数） |

## 推奨組み合わせパターン

### パターンA: 「世界が体に合わなくなる」路線
**S6（環境干渉）+ S5（成長痛）+ S3（服のサイズ）**

ぶつかる、体が痛む、服が合わなくなる。
屈みシステム（既存コア）と合わせて「背が高い人の人生」を**身体感覚**で伝える。

### パターンB: 「成長で世界が開ける」路線
**S1（インタラクション高度）+ S4（視界レイヤー）+ S7（予測）**

身長が伸びるほど新しいものに手が届き、新しいものが見える。
成長＝世界の拡張。ポジティブな発見体験。ただし「大きくなったら
通れない場所」も入れて二面性を出す。

### パターンC: 「全チャンネル」路線
**S6（環境干渉）+ S3（服のサイズ）+ S7（予測）**

ぶつかる→身体的実感。服が合わない→視覚的実感。
予測→未来への関心。3つの異なるチャンネルで成長を感じ取る。

---

## まとめ

**台詞を増やすのは既存の延長。システムを増やすのが新しいゲーム。**

このゲームに足りないのは「テキスト量」ではなく、
**「身長が変わったとき、世界の物理的なルールが変わる」という仕組み。**

> 身長100cmの世界と200cmの世界は、同じ場所でも**違うゲーム**であるべき。
