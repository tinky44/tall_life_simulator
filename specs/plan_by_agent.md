# ゲーム性向上ブレインストーミング

## 前提の整理

### コアの快感
- **身長が伸びる瞬間**が最も気持ちいい
- 「数値が上がる」だけでなく、**視覚的に伸びている**のが良い

### 守るべきもの
- シミュレータとしての自然さ（操作の手間を増やさない）
- 「背が高い人の人生を追体験する」というコンセプト

### 現状の課題
- 成長は楽しいが、成長の**意味**が薄い
- ドアを屈む＝ゲーム性だが、繰り返しは作業になる
- 「できること」が身長で変わらない

---

## 思考法：一人でアイデアを出すためのフレームワーク

### 1. 「操作させる」ではなく「気づかせる」

シミュレータの面白さはプレイヤーの**観察**にある。
ゲーム的な「入力→報酬」ループではなく、
「あ、こんなことが起きてる」という**発見の連鎖**を設計する。

### 2. 「不便」ではなく「変化」

屈む操作を強制するのは「不便の追加」。
それよりも、**世界が自分に対してどう変わるか**を見せる方が豊か。
プレイヤーは何もしなくていい。世界の方が変わる。

### 3. 「足し算」の前に「引き算」

新しいシステムを足す前に、
今ある要素（成長・ステージ・NPC・会話）の**組み合わせ**で
何が表現できるか考える。

## 現状の実装（コード調査結果）

### すでにあるもの
- **NPCパッシブ反応**: 身長差tall/huge/very_hugeの3段階 × ステージ別(school/station/outdoor/room)で台詞が用意済み（`SkeletalNPC.gd` L17-103）
- **子供NPC反応**: 身長125cm以下のNPCが「すごい！ ○○cm！？」と反応（`SkeletalNPC.gd` L105-117）
- **NPC回避行動**: very_huge差で後ずさり、huge差で減速後ずさり（`SkeletalNPC.gd` L324-346）
- **身長イベントキュー**: 170cm/180cm/190cmで `npc_talk_tall/huge/veryhuge` イベント発火（`MainScene.gd` L3024-3037）
- **はるかの身長分岐**: 差15cm→tallバリアント、差35cm→hugeバリアント（`MainScene.gd` L1753-1769）
- **実績システム**: 180/200/230/250/270/300cmで実績解除（`AchievementDatabase.gd`）
- **成長グラフ**: プレイヤーvs平均の折れ線グラフ（`GrowthGraph.gd`）
- **ED比較画面**: 初期・はるか・現在の3体比較（`EndingScene.gd`）
- **カメラ引き**: 身長が伸びるとカメラを引いて相対的小ささを演出（実装済み）

### 既存の仕組みの境界
| 仕組み | できること | できないこと |
|---|---|---|
| `GENERIC_PASSIVE_LINES` | ステージ×身長差で台詞表示 | 1回限りイベントの制御 |
| `queue_event()` / `pop_next_event()` | 1回限りイベントの発火 | 身長閾値での自動発火（手動でif文が必要） |
| `record_event()` / `experienced_events` | イベント重複防止 | — |
| `DialogueDatabase.DATA` | NPC別・キー別に台詞格納 | プレイヤーモノローグの枠組みがない |
| `core_npcs[id]["greet_events"]` | NPCが近づいた時の挨拶台詞 | — |

## アイデア別：実装コスト見積もり

### A. 世界のスケール変化（環境リアクション）

**原理：プレイヤーが伸びると、同じ世界が違って見える**

#### A-1. 背景オブジェクトとの相対サイズ変化
- 小学生のとき巨大だった校門が、高校では小さく見える
- 自動販売機のボタン位置が目線より下に来る
- 教室の天井が近づいてくる

| 項目 | 内容 |
|---|---|
| 必要な変更 | `StageBuilder.gd` のオブジェクト配置にプレイヤー身長参照を追加 |
| 影響範囲 | ステージごとの背景描画ロジック全体 |
| 工数 | **大**（4400行のStageBuilderに広範な改修） |
| リスク | 既存のステージバランスが崩れる可能性 |

#### ~~A-2. カメラワーク/視点の変化~~
- ~~身長が伸びるとカメラの高さが変わり、見える景色が変わる~~
- ~~群衆の中で頭一つ抜ける瞬間~~

**→ 実装済み（カメラ引き）。2D横スクでこれ以上は不自然。除外。**

### B. マイルストーン演出（成長の意味づけ）

**原理：特定の身長を超えた瞬間に「何か」が起こる**

#### B-1. 身長閾値イベント（台詞ベース）
- 先生の身長を超えた → 台詞変化
- 電車のつり革に届く → テキスト演出
- 親の身長を超えた → 家族シーンで台詞

| 項目 | 内容 |
|---|---|
| 必要な変更 | `MainScene.gd` の学期進行時に身長閾値チェックを追加 + `DialogueDatabase.gd` に台詞追加 |
| 触るファイル | `MainScene.gd`（5-10行のif文追加 × 閾値数）、`DialogueDatabase.gd`（台詞データ追加） |
| 既存の仕組み | `queue_event()` + `record_event()` でそのまま実現可能 |
| 工数 | **小**（イベント1つにつき if文1個 + 台詞データ数行） |
| 例 | `if height >= 160 and not global.has_experienced("taller_than_teacher"): global.queue_event("taller_than_teacher")` |

#### B-2. 視覚的マイルストーン（描画ベース）
- ドア枠にぶつかりそうになる演出
- 棚の上が見える演出
- 机が窮屈になる描画

| 項目 | 内容 |
|---|---|
| 必要な変更 | `StageBuilder.gd` にオブジェクトとの干渉判定を追加、専用アニメーション |
| 触るファイル | `StageBuilder.gd`、`SkeletalPlayer.gd`（ポーズ反応） |
| 工数 | **中〜大**（オブジェクトごとに干渉ロジックが必要） |
| リスク | 各ステージ・各オブジェクトの組み合わせでバグが出やすい |

## 推奨ロードマップ

### Phase 1: テキストの力（工数：小）
C-1 → D-1 → B-1 の順に台詞を追加。
**新システムゼロ、既存の仕組みに台詞を足すだけ。**
これだけで「同じゲームなのに世界が反応してくる」感覚が生まれる。

### Phase 2: 比較の可視化（工数：小〜中）
E-3 → E-2 → C-2 の順。
**既存のグラフ・ED画面を拡張して「自分の異常さ」を視覚化。**

### Phase 3: 感情の深化（工数：中）
D-2 → C-3（台詞版）→ E-1。
**選択に意味を持たせ、社会的イベントと身体測定で体験を豊かに。**

### Phase 4: 視覚演出（工数：大）
B-2 → F-2 → A-1。
**描画改修を伴う大きな変更。Phase 1-3の効果を見てから判断。**

## まとめ：このゲームの「ゲーム性」とは何か

従来のゲーム性＝「プレイヤーが操作して目標を達成する」

このゲームの本質＝**「成長する身体と、それに反応する世界を観察する」**

つまり、ゲーム性の正体は**「発見」**。
新しいボタンや新しいシステムではなく、
**同じ操作をしているのに世界の反応が変わっていく**ことが面白さになる。

> 「何もしていないのに、世界が変わった」
> それがこのシミュレータの快感のコア。
